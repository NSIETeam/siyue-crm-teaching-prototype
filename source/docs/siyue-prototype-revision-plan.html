01 · 总体判断

这个原型值得继续做。模块框架、表单构建器、线索时间线和职位权限已经有基础；下一版应把这些页面连成可以完成工作的流程。

目前最主要的问题是：入口划分较完整，但同一任务仍跨多个独立页面；部分“确定”按钮只提示成功，关联数据和结果页没有随之变化。对业务讨论原型而言，下一步最有价值的工作是让模拟数据也能走完任务，并在其他页面看到一致结果。

建议的主链路：课程配置 → 商城详情 → 优惠销售版本 → 客户扫码 / 销售跟进 → 订单与收款 → 选班授课 → 调整与退课。顶部搜索、角色工作台和 Agent 共用这些业务动作。

本方案保留原型现有文件和页面基础，给出逐页修改、流程关系、优先顺序和验收场景。没有修改原型目录，没有执行真实业务。

02 · 判断依据与可保留部分

对象：CRM教培系统原型-20261010/index.html，以及 academic、leads、shortcuts、mall、marketing-forms、structure、permissions 七个脚本。结合本对话已确定的需求及项目 v2 文档核对。原型说明明确人员、线索和金额为演示数据。

本地 file:// 页面被浏览器工具的协议安全策略阻止；本轮依据源码核对页面结构、事件处理和数据关系。下文“已有”指代码已表达，不表示浏览器端到端验收通过。内存演示和未接真实支付本身不作为缺陷；重点是原型有没有准确表达你的业务。

保留的基础为什么保留在其上继续补什么
线索今日待办、我的线索、详情时间线已围绕销售工作组织，不必重新设计整套 CRM。员工真实身份、归属与保留期限、转交和公海分配。
登记人和当前负责人分别统计转交后还能追溯谁带来线索，符合来源与销售归属分离。活动来源、入口、采集人、提交人、归属变更记录。
课程上架直接读取教务课程已经走在一次维护的正确方向。完整商品详情草稿、稳定课程标识、优惠销售版本。
营销表单组件、家长端预览、填写记录、资料领取是现成的扫码获客界面基础。任意获客表单都能按配置建线索，而不是仅资料下载表单。
三步报名与线索转报名已能带入部分上下文，适合作为统一成交任务。预购、报价、待支付 / 到账、权益和班级名单联动。
课程、班级、考勤、补课和业务办理入口模块划分可作为管理视图继续使用。课次、内容与个人权益模型；从学生或课表直接发起任务。
职位授权、未保存提醒、权限差异日志已有权限配置和可追溯体验，值得复用。操作权限、校区和本人范围、身份首页、同规则 Agent。

05 · 逐模块修改清单

核心

1. 首页与大搜索：让身份决定工作，不再默认进入配置

当前：顶栏只有面包屑和演示身份；默认页面是系统配置。已有销售今日待办，但使用固定员工名，切身份不等于切换实际负责人的数据。

改法：新增首页作为默认落点。销售显示本人待办、持有线索和个人数据；校长显示授权校区汇总。顶部搜索同时返回对象、可执行动作、进行中事项；选中后打开统一任务面板。角色切换同时更新当前员工、校区范围和可用动作。小屏保留搜索和身份范围入口，不继续隐藏整个顶栏。

下一版要能演示：销售甲和销售乙看到各自线索；校长看到本校区；从搜索“学生甲 续费”进入带入学生的报价任务，与卡片按钮结果一致。

源码定位：index.html:97,101；leads.js:25–26；shortcuts.js:2；permissions.js:51–58。本轮未做浏览器运行验证。

核心

2. CRM：现有三个归属选项保留，但按身份与来源执行

当前：登记表已有“我自己 / 统一分配 / 指定招生岗”和候选员工推荐；但默认归属固定为演示员工，缺保留到期和独立交接流程。公海混在新线索、回收池等标签里，期限仅有固定说明。

改法：销售录入或销售专属码的新线索默认本人保留；运营、地推、私域及一般活动入口进入公海，管理员分配。来源渠道、提交人、采集员工、当前销售分开保存。线索卡片增“转交 / 释放”；回收策略配置保留期、首跟进、有效跟进、提醒与续保，具体数值待定。已有有效归属遇到重复扫码只追加触达，争议进入核对。“冷宫池”改为已归档；预警作为附加标记，不替代当前归属和跟进阶段。

下一版要能演示：两类入口形成正确归属；销售可把自己的线索交给允许接收的同事或放回公海；回收后记录与预约完整，旧归属失效；普通销售不能分配任意公海线索。

源码定位：leads.js:25–31,66–120,123–126；shortcuts.js:36–58；permissions.js:14。本轮未做浏览器运行验证。

核心

3. 扫码表单：将“建线索”从资料下载开关中独立出来

当前：表单可编辑、预览、记录填写和提交后领取资料；但 mfCaptureLead 只有开启资料下载才建线索，普通咨询填写可能只有表单记录。

改法：在表单设置增加用途：线索采集、预约体验、商品报名、普通调研；线索采集默认创建或关联线索，字段映射独立配置。绑定活动、来源和入口归属；资料领取只是提交后的可选动作。预览时显示“提交后将进入销售本人 / 公海”，便于运营发布前核对。

下一版要能演示：没有资料附件的咨询表单提交后仍进入正确线索池；同一手机号有两个孩子时先关联家庭再区分意向，不把第二个孩子吞掉。

源码定位：marketing-forms.js:33,39–45。本轮未做浏览器运行验证。

4. 课程 → 商品：沿用共享课程，补详情、章节和版本

当前：商城已经读取教务课程；但商品详情只提示文字，价格和老师为固定展示。课程表单虽然有讲次和费用，saveCourse 没有保存这些字段；编辑也无法完整回显。

改法：把课程表单扩成“基本 / 章节资料 / 商城详情 / 销售版本”工作区。每讲保存内容标识、目标、时长与资料；增加年龄范围。商城详情由公开课程字段派生，营销只补封面和摘要。课程版本、销售版本和班级分开；教学资料不全部公开。上架状态绑定稳定课程标识，新增课程不能使原上架记录串到另一门课。

下一版要能演示：填写后再次打开全部回显；课程变更产生商品差异预览；同课程可有标准、续费两种销售版本；旧订单内容与价格不随新版本改写。

源码定位：academic.js:19–21；mall.js:3,17–29。本轮未做浏览器运行验证。

5. 优惠 → 销售版本 → 扫码：把活动配置接到学员收费

当前：已有拼团、联报、优惠券及商品选择；推广目前是演示提示，报名侧仍为固定金额和待补优惠规则。

改法：保留拼团、联报、券作为可复用规则组件，增加老带新、双人同行、续费模板。选课程后发布“优惠销售版本”，展示资格、价格条件、有效期、可售范围和退款影响；界面设置的条件必须保存后可回显、试算和解释。生成可传播的活动入口码；识别具体学员并报价后再生成绑定订单的付款码。学员卡片显示可用收费策略和资格来源，历史成交另存快照。

6. 报名与收款：区分“建单、付款、权益、入班”

当前：报名已有三步和三种收款方式文案；finishEnroll 将输入的实收写入订单后统一标记交易成功，即使为零。线索转报名会先创建学生，重复发起可形成多份演示档案。

改法：继续使用三步流程，但第二步允许选课程预购或现在选班；第三步读取统一报价。未付、部分付款、已付分别显示；获授权的欠费入班独立表达。选择已有学生或建立关联，避免每次发起都新建。到账后生成权益，选班再生成安排；已付未选班进入教务待办。

下一版要能演示：零实收的待付单不会显示资金交易成功；模拟重复支付回执只记一次；取消后再次发起报名仍使用同一学生；已付预购后选班不重复收费。

源码定位：academic.js:34–40；leads.js:32；shortcuts.js:24–27。本轮未做浏览器运行验证。

7. 班级与课表：从班级起始日期变成具体课次

当前：班级详情实际进入编辑表单；课表有时间、老师和教室标签，但主要按班级起始日期展示，没有学生视角、起止区间和按课次办理。

改法：班级详情增加讲次、当前 / 历史学生、实际进度、记录四块；编辑配置退居独立按钮。排课生成逐次课表并引用内容标识。新增校区、教师、学生视角，保留教室视角；起止日期与课程、班级、状态筛选叠加。点课次打开侧栏，自动带入对象后做点名、调课、调班或代课。

下一版要能演示：同一个学生的临时转入课次可见、取消的原课次不进入有效列表；三个视角读到一致教师与学生安排；操作后保留筛选位置。

8. 调班、代课与授课：从独立填表变成带上下文办理

当前：临时调班允许分别选择两边“第几讲”，没有相同内容校验；完成只显示提示。未发现独立代课操作路径，出勤记录与实际内容完成也未分开。

改法：从学生具体课次发起，自动按内容标识与版本推荐目标；过滤名额和时间冲突，一次预览取消与新增安排，其余原班课次保持有效。永久转班另设生效日期和缺讲处理。代课只修改指定课次的授课老师，并带交接资料；保留班级主讲。记录实际授课、学生出勤和课消三个事实。参考平台“不支持某类型课程”的提示不直接当作思跃的已定规则。

下一版要能演示：同讲号不同内容不会自动匹配；满员失败后原安排还在；成功后两班点名册同步变化；代课两讲不改整期主讲；请假不凭日历推进个人已学。

9. 退课与财务：一张事项显示教学退出和退款结果

当前：退课金额固定展示为 1000、已上 1/3、应退 666.67，提交仅提示；退转记录与课消记录仍是空结构。

下一版要能演示：演示一门优惠课程已上数讲后的退费；学生从未来有效点名册消失，历史保留，退转与财务记录能找到同一事项；退款失败可重试而不再次取消或恢复课程。

10. 权限与 Agent：在已有职位配置上增加范围和动作

当前：有职位授权、未保存提醒、差异日志和入口拦截；目前主要是页面级授权，单个员工绑定一个职位。某些“负责人只读”的限制只在具体页面内处理，不能证明其他业务动作均只读。

改法：员工支持主身份、兼岗身份和校区 / 团队范围；每类业务再设查询、编辑、分配、发布、退费确认等动作权限，停用员工先显示线索与课次交接事项。角色首页和搜索按同范围返回结果。Agent 调用与按钮共用的“查找 → 预览 → 按授权执行 → 读回”动作，保留实际操作人、任务状态与日志；无须为每项常规动作增加一次人工确认。原型阶段可用明确标识的脚本情境演示三条任务，不必先接真实模型。

下一版要能演示：只读身份进入线索详情不能修改、转报名或分配；销售只能对本人或被授权对象操作；按钮、全局搜索和 Agent 在同一权限下得到相同结果。

源码定位：permissions.js:2–43,51–64,92–109；各业务提交函数。本轮未做浏览器运行验证。

06 · 先修复会干扰业务讨论的演示问题

这些修复不要求先接后台。只要保留本地模拟状态，就应避免演示出错误的业务结果。

问题下一版应如何改可复现的验收
课程和班级共用 selectedClass 索引分别维护课程、班级和具体课次的选中标识；从课程创建班级时明确为新建并带入课程。从第二门课程点“创建班级”，不会打开或改写第二个已有班级。
编辑班级重新生成 ID，默认人数 0、未开课创建与更新分开；仅修改允许编辑字段，保留原标识、学生安排和状态。已开课班级改一个名称，原学生和进度继续存在。
商城用课程数组下标记上架关系改为稳定课程 ID 与销售版本 ID，后续插入 / 排序不改变关联。新建课程插到第一行后，原已上架课程不串位。
新生信息只在第一步输入框内，跨步骤未保存建立报名草稿，保存姓名、联系方式、校区和所选课程，返回上一步继续回显。新生走完三步后订单仍对应刚填写的学生，不能退化为“新学生”。
“我的线索”部分分支只按 stage/status 筛选从当前员工与数据范围出发，再叠加阶段筛选；阶段与归属分开。销售甲在“已报名”页不看到销售乙独有线索。
修改线索时来源下拉未完整回显普通修改保留原来源；修正来源用单独动作并留痕，归属交接不重写来源。资料领取线索改一条备注后，来源仍是原活动 / 入口。
默认全局固定业务数字影响认知演示金额、名额和进度从同一模拟数据计算；标注样例规则。改付费数或已上课数后，报价 / 退款 / 名单出现相应变化。

源码定位：academic.js:16,21,24,37–42；mall.js:3,17–28；leads.js:25–26,86–120。本轮未做浏览器运行验证。

07 · 页面共用哪些事实

不必立刻更换前端框架。先给现有模块一个共用的数据与动作层，使相同按钮、搜索和 Agent 不再各写一套规则。

共同事实页面如何使用要分开的状态
员工身份 + 校区/本人范围工作台、线索、搜索、审批与操作按钮能看页面 ≠ 能操作任意对象。
客户家庭 / 学生 + 线索 + 归属扫码表单、我的线索、公海、转报名来源、采集人、负责销售、跟进阶段分别记录。
课程版本 + 内容单元 + 商品详情课程、商城、班级、教案与进度公开商品信息与内部资料分开。
优惠销售版本 + 学员资格 + 报价快照活动、销售报价、商城支付、后续收费当前策略与历史成交规则分开。
班级 + 课次 + 学生上课安排课表、点名、调班、代课与补课整期归班与一次调整分开。
订单 + 支付 + 学习权益 + 消耗记录报名、财务、授课、退课订单创建、到账、可上课、已入班、已消耗分别显示。
任务 / 审批 / 外部结果首页待办、所有快捷操作、Agent业务完成与通知、资金回执分别追踪。

下一版原型先用模拟数据证明关系，随后接入真实接口。每个任务至少返回“改了哪些记录、当前状态、失败原因和下一步”，不能只弹一句“已记录”。

08 · 下一版要能连起来的两条完整业务线

这两张目标流程沿用项目 v2 的业务规则；此次重点是把原型现有页面放回各自节点并补齐断点。

课程、优惠与收款

从 courseForm 进入商城详情预览，由 mallForm 选择模板并生成销售版本，最终进入同一个 enrollPage 报价和收款任务。

采集、保留、公海与回收

marketingForms / quickRegister 负责入口，myLeads / leadDetail 负责本人跟进和交接，leadManage 负责管理员分配与策略回收；它们改变同一份归属事实。

09 · 建议按三个批次改，逐批演示验收

批次具体范围交付判定
A · 先能看到和处理自己的工作修复误改班级 / 错误成功状态 / 索引串位；统一身份与对象标识；新增首页和顶部搜索；接通扫码建线索、本人保留、公海分配、转交与回收。客户扫码后，在正确的人或公海中出现；切身份后范围正确；销售能带入线索继续报名草稿。
B · 课程能直接卖课程章节资料与商品详情自动派生；三类优惠模板、销售版本、统一报价、模拟收款与待选班；同一学生收费策略可查看。演示“新课程 → 优惠发布 → 客户扫码 → 订单 → 到账 → 权益”，历史快照不变，金额解释完整。
C · 授课和突发能连续办完具体课次、多视角课表、班级详情、内容调班、代课、个人进度、退课与资金两条状态；完善异常待办。完成下表全场景；任务办完后，课表、名单、进度、订单和资金状态相互一致。

这不是工期估算。三个批次都沿用共同动作与权限，Agent 从第一批即能调用同一入口；跨校区、复杂套餐、批量调课等能力在基础流程稳定后扩展。

10 · 用这些场景评审下一版

场景必须看到的业务结果
运营活动采集与销售专属采集各提交一条新线索前者进公海，后者归销售本人；重复提交不改已有有效归属。
销售放弃一条线索并指定同事，另一条到期回收分别进入新销售待办 / 公海，客户约定、历史、来源均保留。
普通咨询表单不开资料下载仍按表单用途创建 / 关联线索，而不是只出现填写记录。
新建课程再查看已上架商品课程信息自动填详情；原有上架关系不因新增课程改变。
同课程分别发布续费版与双人同行版学生资格与条件可解释；入口与订单可区分；不复制教学课程。
未付款、部分付款、重复回执各有正确状态；无条件零实收不显示资金成功；重复回执不新增权益。
已付款但尚未选班教学权益存在且进入待选班；后续选班不重复建订单或收费。
同讲号不同内容 / 同内容但目标满员不直接调入；原安排保留；可换时段或目标班重试。
只调整学生一讲、只为老师代课两讲其他原班课次有效；班级主讲不变；三种课表和点名册一致。
优惠后上了数讲再退课，模拟退款失败按实收分摊与实际消耗试算；未来名单移除、历史保留、财务继续处理。
销售、校长、只读负责人从搜索进入同一对象结果与动作分别遵守范围；不能通过搜索或 Agent 绕过限制。
