1. 改造方向：用一条任务完成一件事

建议把集团平台改造成覆盖营销招生、CRM 销售、课程教学和财务的统一工作系统：教务发起“给学生报名”“调整这一讲”“安排代课”“退出这门课”，系统带入已有信息、计算影响、检查冲突，并把相关变更一次完成。页面操作与 Agent 操作应调用同一套业务能力。

集团已经存在课程与班级、预购与选班报名、学员排课、调整申请与审核、退费确认、学期优惠和优惠券等业务入口。本次改造应复用其中可靠的业务事实和规则，把分散入口组织成连续任务；不应把现有平台概括成“没有联动”，也不应要求为了报名先虚构一个班级。

主链路调整为“课程一次配置 → 商城商品 → 优惠销售版本 → 线索与销售跟进 → 扫码报价收款 → 选班授课 → 调整与退课”。角色首页、顶部搜索和 Agent 贯穿全程。招生端与教务、财务共用事实和规则，同时保持报名不重复录入、调班不丢讲不重讲、代课不误改主讲、退课不遗留未来有效点名项。

  • 学生买了什么：订单、实际收款、优惠分摊与课程权益。
  • 学生接下来在哪里学：阶段归班、具体课次安排与临时调整。
  • 学生实际学了什么：授课内容、个人出勤、权益消耗和待补内容。

三类事实分开保存、联动展示。临时转班改变一次上课安排；永久转班改变未来归班；代课改变指定课次的教师；退课同时处理权益退出、未来安排和退款，但不抹掉历史学习与资金事实。

5. 身份工作台、顶部搜索与员工权限

顶部统一入口：搜索对象，也能直接说要做什么

搜索框支持学生、家长、线索、课程、班级、老师和业务单据，并支持“给这个学生生成续费收款码”“查看某校区下周课表”“把这条线索转给销售乙”等自然语言任务。结果按“对象 / 可执行动作 / 进行中的事项”展示；选中结果后在任务面板继续办理，自动带入上下文。输入名字只查询，明确动作才进入办理；同名或范围不清时展示候选。

搜索提示、结果数量、明细和操作按钮均遵守当前身份及校区权限。课程报价、发布收款码、调班等动作与列表按钮调用同一能力；Agent 不能通过搜索绕过角色限制。用户始终可以通过常规按钮完成同一件事。

员工身份设置

员工档案关联所属校区、团队、岗位身份及有效期。身份模板定义功能权限，数据范围再限定“本人 / 团队 / 本校区 / 指定校区 / 集团”；最后配置可办理动作和例外额度。一个员工可以兼任身份，切换工作视角时清楚显示当前职责和范围，不能隐式扩大可见数据。

课程与营销编辑课程、查看内部资料、审核商城详情、创建优惠、发布销售版本、停用入口。

学生 / 客户卡片与任务连续性

卡片聚合线索来源、当前销售、跟进记录、学员收费策略、已购课程、下一课次、个人进度、剩余权益、订单及进行中事项。学生与监护人关联清楚，同一家庭多个孩子分别办理；高频信息直接显示，低频材料按需展开。任务保存草稿、状态、责任人和下一步，切换页面后可续办；历史重复档案需核对后合并。

6. CRM：线索创建、销售保留、公海分配与回收

本轮用户确定：客户扫码填写是主要建线索方式。课程销售采集或录入的线索默认预先保留给本人；销售放弃保留可以指定给其他销售。运营、地推、私域、活动等其他来源进入公海，由管理员统一分配。系统需要线索分配与回收策略，并对接公司销售人员。以下期限与阈值仅列为待配置项，不预设天数或数量。

用户路径：采集后立即知道归谁、下一步做什么

  1. 创建入口：为活动、渠道或课程销售生成采集二维码。客户填写联系方式、孩子与意向课程等必要信息；员工代录时标记代录身份，不把员工当作客户提交人。
  2. 校验与归属：系统检查重复与已有有效归属。新线索由课程销售专属入口采集或该销售录入时，默认保留本人；其他来源进入公海待管理员分配。
  3. 销售跟进：个人首页显示待首跟进、待回访、即将到期和待处理冲突。打开客户卡片即可记录跟进、预约试听、生成报价并转报名。
  4. 放弃或移交：销售明确放弃保留时，可指定有接收权限的其他销售，或释放公海；处理结果同时更新双方待办，保留交接原因和记录。
  5. 管理员分配与回收：按校区、意向、员工状态和工作量筛选公海，批量或逐条分配；符合已发布回收策略的线索回到公海，继续保留全部跟进历史。

系统联动：来源与负责人分开保存

一条线索分别记录：客户来源渠道、入口活动、实际提交人、采集员工、当前归属销售、归属变更历史。归属判定使用已登记的入口和员工身份，客户表单不能任意指定或覆盖负责销售。地推采集员工不自动获得课程销售归属；销售专属入口可来自某场活动，归属给销售时仍保留该活动来源。移交、回收或成交不改写原始来源，后续触点追加记录；营销贡献和销售业绩使用各自明确口径。

线索关联监护人与学生意向，转报名复用档案、课程意向和归属，不重新建立同一家庭。同一手机号可能对应多个孩子，一名孩子也可能有多个监护人；匹配到家庭不等于把所有孩子、所有新意向无条件合并。已有有效归属不因重复扫码、员工补录或新活动触达而被抢走，冲突进入有依据的归属判定。

环节 / 状态确定的目标行为建议配置或待明确项
新线索 → 销售保留校验无有效冲突后，为销售本人保留；写入时间、渠道、入口和负责销售。保留期限、个人上限、跨校区资格、销售身份识别方式。
新线索 → 公海待分配非课程销售归属来源进入公海，由管理员统一分配，不默认为采集员工私有。公海按校区或业务范围分区、管理员权限、批量分配规则。
已分配 → 跟进中生成销售待办，保留跟进内容、下一步和约定时间。首跟进时限、何种记录算有效跟进、是否需要接收确认及拒收处置。
主动移交 / 释放销售放弃后指定其他销售或进入公海；记录原归属、新归属和移交理由。接收者适用范围、停用员工处理、越范围交接审批权限。
到期 / 无有效跟进 → 回收按配置策略回收，旧归属失效，历史与客户约定随线索保留。回收阈值、提醒、续保理由与审批、重复回收、离职或停用交接规则。
成交 / 暂不意向 / 无效记录结果与原因，成交关联学生、订单和实收；客户记录继续存在。已有学生再次咨询的负责人、重新激活和结果更正规则。

异常与验收

  • 重复手机号、姓名相似、家庭多孩、跨校区重复咨询应展示匹配依据；无法确定时转人工核对，不静默合并或变更归属。
  • 管理员分配、销售移交和自动回收同时发生时，只允许基于最新归属完成一次有效变更；过时操作提示当前负责人并重新确认。
  • 被回收线索仍保留跟进、预约及客户承诺，新负责人可续办；停用员工的未完成线索进入交接队列，不成为无人负责的隐藏记录。
  • 验收：销售入口创建后出现在本人首页；其他入口进入公海；管理员分配后双方列表同步；重复扫码不抢归属；移交后来源统计不变；回收后历史完整且原负责人无继续执行专属操作的权限。

7. 统一对象与进度口径

这是所有流程能够一次完成、可追溯和可由 Agent 调用的基础。下表为建议模型，并非对集团现有数据表的断言。

对象表达的事实不能混用的对象
客户、线索、销售归属谁咨询、来自哪里、为哪个孩子咨询、当前谁跟进，以及分配/保留/回收历史。采集人、客户提交人、活动来源与负责销售不能合成一个字段。
商品、优惠销售版本、学员收费策略课程如何公开售卖、适用哪组优惠，以及某学员当前符合哪些条件。商品展示不等于内部教案；当前收费策略不等于历史订单成交快照。
员工身份与数据范围谁可以查看或办理哪些事情、覆盖哪些校区或学生。首页展示、数据归属、操作授权和业绩归因分别定义，不能由页面隐藏代替权限。
课程与发布版本教什么、适合谁、使用哪些资料、标准价格和课时结构。课程版本不等于一个具体班级，也不等于订单实际成交价。
章节 / 内容单元稳定内容标识、顺序、课时和前置要求。“第 3 讲”是顺序编号，不能独自证明两班内容相同。
班级、阶段归班持续教学组织及学生在一段时间内的归属。不能仅凭班级成员关系推导所有临时上课安排。
课次、学生上课安排何时、何地、谁教哪一讲，以及哪些学生计划参加。计划参加不等于已经到课或已扣课。
订单、支付、课程权益应买什么、实际收了多少、学生可学习什么。报名成功、支付成功、选班成功是不同状态。
出勤、授课、权益消耗学生是否参加、实际讲了什么、按何种规则消耗多少权益。缺勤不必然不扣课；课程日期已过不必然已经讲完。
调整事项、退款事项谁请求了何种变化、影响范围、处理进度和最终结果。审批通过不等于支付渠道已经退款成功。

用户动作

在课程、班级和学生视图查看对应进度，并从缺讲、冲突、剩余权益等事实直接发起任务。

系统联动

同时展示三种口径：班级计划排到哪一讲、班级实际讲完哪些内容、学生本人完成哪些内容。学生请假后，即使原班继续上课，个人进度也不自动推进；转入进度更快的新班，应形成待补内容清单。

异常与待决策

同一班是否允许关联多门课程、一个实际课次能否合讲或拆讲、跨版本内容如何判定等价，需要明确业务规则。历史数据缺失稳定章节标识时应先补映射，再启用自动同章节调班。

8. 课程模板、内容、资料与版本

已观察：学而思参考平台有年份、学期、学科、班型、年级和讲次名称字段（W2）；集团课程列表包含年度、学期、科目、年级、单价、节数、总价、优惠、老师和班级数，并提示同一课程下各班型单价与节数一致（G2）。年龄细分、课程资料绑定与内容版本管理在本次未完整验证。

用户动作

  1. 从模板复制或新建课程，确定学科、学段、适龄范围、能力前置条件和售卖范围。
  2. 逐讲填写主题、学习目标、标准时长、章节顺序、课件和课后材料。
  3. 设置标准价格、资料是否独立售卖、优惠适用范围及已确认的退费规则。
  4. 同时预览课程大纲和由课程信息自动填充的商城商品详情；检查公开字段后发布课程版本与商品展示，优惠销售版本另行选择模板生成。

系统联动

课程名称、适龄范围、大纲、课时、公开资料、标准价格和开班范围自动映射到商城商品草稿，不再到商城重新填写；内部教案、答案和学生信息不自动公开。商品详情与课程保持来源关系，具体发布与收款流程见“课程商品化”章节。模板负责复用，发布版本负责稳定履约。已经售出的版本保留内容、价格与规则快照；修改下一期课程不会悄悄改变原学生权益。班级引用课程版本，排课时自动带入讲次与资料。教师从课次进入即可得到本讲所需资料，代课教师获得同样范围内的临时访问。

异常与待决策

  • “年龄”与“年级”可并存；生日、年级与能力不一致时给予提示，是否允许例外由课程规则和权限决定。
  • 仅修正文案和实质替换内容要区别处理；实质改版需要新版本与旧新章节的衔接说明。
  • 集团现有“各班型单价、节数一致”的限制是否仍符合业务，应依据真实班型样本决定保留或调整。
  • 资料购买、领取、下载与实际使用分别记录；资料是否可退须有购买时明确的规则。

9. 课程商品化、优惠版本与扫码收款

本轮用户确定：设置课程时自动填充商城商品详情；创建优惠策略后，选中课程并发布相应优惠销售版本；优惠提供老带新、双人同行、续费等预设模板，并关联学员收费机制。收款偏好：以扫码支付为主要候选入口，支付服务商与具体结算方式尚未确定。以下联动和异常规则为落地建议，不是对现有平台能力的观察结论。

用户路径：设置一次课程，完成一次发布

  1. 课程负责人设置课程：名称、适龄与年级、学习目标、逐讲大纲、课时、公开介绍、标准价格、校区和可选班级自动组成商城商品详情草稿；只补封面、宣传摘要等必要营销信息。
  2. 营销选择模板：选老带新、双人同行或续费，配置适用课程、学员条件、优惠内容、有效期、名额和叠加规则，查看典型订单试算。
  3. 选课发布优惠版本：选择课程或课程组合，预览商品页、优惠说明、可售范围及收款入口；确认发布后得到推广链接与入口二维码。
  4. 客户扫码报名付款：识别学员、选课与选班或预购，系统匹配优惠并展示明细；生成待支付订单和付款入口。销售也可在客户卡片上生成同一报价的学员订单码。
  5. 确认到账并交接：收到并校验实际支付回执后更新订单、实收、学生权益及待选班任务，关联销售与活动归因。

系统联动：课程事实复用，成交事实留存

商城字段映射课程主档，避免两处填写课时、大纲和价格。营销文案可独立编辑；教学课件、答案、内部备课资料默认不随商品公开。修改课程时先标出商品页差异，再发布新版本；已售权益继续引用成交版本。班级时间和余位展示读取有效课表，不在商品文案里维护另一份名单。

每位学员的“收费机制”展示当前可适用政策、资格来源、有效期与预计报价。政策发布或学员资格变化会更新后续报价；已支付订单保留成交时的优惠、分摊和规则快照，不被追溯改价。未支付报价到期后重新试算，新增优惠是否替换仍有效的报价需明确提示。

对象 / 模板状态与规则建议必须明确的配置
课程商品与优惠销售版本草稿 → 待发布 → 已发布 → 停售 / 到期。优惠版本引用课程和规则版本，原标准售卖版本可按业务需要并存。发布权限、售卖校区、库存 / 名额、预购范围、活动停用后的未付订单处置。
老带新保存推荐关系，先核验新生资格；优惠与推荐奖励分开记录，按约定事件生效。新老生定义、推荐关系确认点、双方获益、退款后奖励如何冲回。
双人同行关联两名符合条件的学员和订单；分别展示资格待满足、已满足、已失效，避免一人重复凑数。是否同课程、组队期限、先优惠后补足还是满足条件后返还、单方退课处理。
续费依据既有购买或学习事实识别资格，同一学生后续订单自动匹配。续费窗口、课程范围、跨科跨校区是否适用、与其他活动是否叠加。
二维码与报价活动入口码携带商品、活动、渠道信息；学员订单码对应确定订单与锁定报价。二者不可混为可任意修改金额的通用码。报价锁定期限、订单失效条件、支付方式、外部收款结果确认途径。

异常与验收

  • 活动已过期、名额已满、学员不符合资格时，阻止旧入口直接成交，展示原因和当前可选报价；不能悄悄按更高金额收款。
  • 支付成功页或截图不能替代到账回执；重复回执只记一次。报价过期后的迟到到账进入核对，不自动重复收费或无条件占用已售完名额。
  • 验收：课程改一处能生成详情差异；三类模板能解释适用与不适用原因；同一学员在销售端和商城得到一致报价；改策略不改变历史实收及退款基础；实际到账后仅生成一次权益。

10. 建班、多视角课表与快捷操作

已观察：参考平台把课程、班级、校区、教室、老师、容量、调课虚位、周频、停课日和讲次日期集中在建班流程，并提醒改动日期、频率或时间会重置课表（W3）。集团班级列表已有班额、总课时、已排课时、教师、教室、单双周和负责人等（G3）。

用户动作

  1. 从课程版本发起“开班”，选择校区、主讲教师、教室、容量和开课区间。
  2. 选择周频与固定时段，系统生成逐次课表；教务只处理节假日和例外。
  3. 查看教师、教室和已选学生的冲突，确认后发布。

系统联动

课表每行同时关联时间和内容，不只生成日期。修改排课规则后先展示差异：哪些课次改变、哪些学生受影响、哪些已有记录不能覆盖。容量由有效上课安排与有效占位共同核验；临时转入名额要有清楚的容量政策。

课表查询与点击办理（用户已明确）

课表既用于看安排，也是高频操作入口。顶部选择起止日期，可切换日、周、月或自定义时间段，并从校区、教师、学生三种视角进入；三种视角读取同一批有效课次和学生安排，不维护三套独立课表。

视角可叠加筛选点开课次的快捷操作
一个校区的一段时间课程、学科、年级、班级、老师、教室、时间段、开课/停课/待安排等状态。查看班级与名单、改时间/教室、安排代课、停课、补排；校长可从异常直接进入处理。
某位老师的一段时间校区、课程、班级、本人主讲/临时代课、待点名/待记录状态。点名、授课记录、打开本讲资料；有权限时发起代课或调整。
某位学生的一段时间课程、班级、校区、计划/请假/临时转入/补课/已取消及出勤状态。调整这一讲、请假与补课、查看实际已学、从课程发起转班或退课。

点开课次先显示章节、时间地点、计划与实际教师、参与学生和调整标识，再按身份提供动作。任务自动带入所点课次；修改前展示影响和冲突，确认后刷新各视角，保留当前筛选与滚动位置。批量操作必须先列出明确选中的课次和学生，不把“当前筛选”默认为全部修改。

学生视角默认展示有效安排，临时转班后原课次只在“含已取消”视图出现，目标课次和其余原班课次均可见。教师视角按实际授课安排识别代课，原主讲能查看变更记录但不重复计算授课负荷。权限不足时可查看允许的详情，并把办理事项转交有权限人员。

异常与待决策

  • 冲突不能只有一个全局“允许冲突”开关；区分提醒、禁止和有权限的例外，并记录理由。
  • 已发生的授课不被重新排课覆盖；未开课与已开课班级使用不同变更范围。
  • 集团现有说明中，结课后不可编辑，空课节时结课会删除班型（G3）。目标流程应先展示明确后果；是否保留删除行为须单独评审。
  • 教室容量、线上课并发容量、候补和临时虚位是否统一计算，需确认机构政策。

11. 报名、预购、选班与收款

已观察：参考平台采用三步报名（W4）；集团购课支持先搜已有学员，并明确支持“尚无班型、后续教务排课”的预购，以及指定最多购买几节的选班报名（G6）。

用户动作

  1. 选择已有学生或创建必要档案，补充本次报名缺少的信息。
  2. 选择课程与购买范围，进入“现在选班”或“先买后选班”。
  3. 系统展示可用优惠组合和完整报价，教务确认付款方式、合同约定与必要例外。
  4. 完成订单与收款；立即选班者确认未来安排，预购者进入明确的待选班状态。

系统联动

原价、优惠、资料费、赠课、应收、实收分别显示。成交时保存规则和分摊快照，防止后续调班或退费重新读取已变化的营销规则。选班引用已有权益，不能再次生成收费。支付未完成时，明确显示是否占位、占位期限及到期释放结果。

异常与待决策

  • 一个付款人对应多个学生或课程时，订单项必须准确关联学生和权益，不能按整单总额计算单个学生退费。
  • 预购、分期、余额支付、赠课、授权欠费上课和补差价均需分别确认状态规则。
  • 部分课程中途报名时，购买的是剩余章节、指定章节还是一定课时额度，不能只用“买几节”掩盖内容范围。
  • 付款回调迟到或重复时只形成一次有效收款和权益；已过期占位要重新检查名额。

12. 授课、出勤、课消与补课

已观察：参考平台有按老师、班级、日期处理未考勤的入口，页面提示每天 24 点锁定当天已考勤学生；补课列表包含学生、班级、讲次、时间、出勤和补课状态（W9、W10）。已有班级详情可按讲次查看考勤和发起临时调班，列有讲次名称、时间、学生数与讲义下载次数（W11）。锁定后的更正机制本次未验证；班级显示进度与讲次待考勤并存，不能把列表进度直接当成学生实际课消。

用户动作

  1. 老师进入“今天的课”，查看本讲内容、资料与有效学生名单。
  2. 快速点名，记录请假、缺勤等例外；确认实际讲授内容与完成程度。
  3. 对需要补课的学生选择处理方式，查看后续补课任务。

系统联动

点名册来自该课次的有效上课安排，临时调入、调出与已退课学生自动反映。出勤状态与课消规则分开：依据课程、订单和已确认政策生成消耗记录，更新剩余权益。授课记录更新班级实际进度；个人完成内容依据实际参加和业务确认更新。

异常与待决策

  • 请假、旷课、迟到、试听、赠课、补课分别是否扣课，必须建立清晰规则，不预设“一律到课才扣”。
  • 老师未讲完计划内容时，不把日期经过当作讲完；下一次内容衔接需要显式调整。
  • 锁定后更正走有原因的更正流程，并同步冲正错误课消；不能直接覆盖历史。
  • 补课来源关联原缺课事实，避免原课与补课重复消耗；是否需要额外付费按明确政策计算。

13. 临时转班：默认调整到相同内容

已观察：参考平台按学生、调出班级与讲次、调入班级与讲次选择（W5）；自动同章节匹配未验证。以下是满足用户目标的建议流程。

用户动作

  1. 从学生下一节课或点名册点击“调整这一讲”，默认带入课程、原课次及章节。
  2. 查看相同内容的候选课次，按时间、校区、老师和可用名额筛选。
  3. 确认影响单：原安排取消、新安排生效、何时回原班、是否有额外费用或内容冲突。

系统联动

同章节匹配使用稳定内容标识，默认同课程版本；跨版本仅使用已维护的等价关系。确认时重新检查目标名额与学生时间，同时使选中的原安排失效并建立目标安排。原班对应点名项退出有效名单，新班点名项生效；归班关系和其余原班课次始终保持有效，按各自课表继续，不必等目标课次上完才恢复。提交时一并检查后续重复、缺讲和时间冲突。

异常与待决策

  • 找不到同章节时，清楚显示无匹配结果，提供其他时间、校区、补课或有依据的例外，不静默跳章。
  • 同为“第 5 讲”但版本内容不同，不视为相同；拆讲、合讲需要明确的内容与课时映射。
  • 目标课次停课、变更内容或容量被占用时，原预览失效，进入重新安排。
  • 学生回原班后若将重复刚学内容，应提示并明确后续安排；有意复训需单独标记和扣课规则。
  • 连续多次临时调整可一次选择范围，但预览必须逐次列明匹配和回班日期。

验收标准：同一个学生、同一权益、同一次内容履约只保留一个有效待上课安排；原安排取消与目标安排生效必须同时成功，失败时两边都不改变。

14. 永久转班与跨课程转课

已观察：参考平台永久转班有独立入口，选择转出与转入课程班级及经办信息（W6）；集团有转班与课节变更入口（G5）。实际跨课程差价和权益迁移规则未验证。

用户动作

选择学生、课程、生效日期和目标班级；查看原班与新班的内容对照，明确待补讲次、重复内容和差价后确认。若更换了课程产品或权益范围，界面明确进入“转课”，单独确认权益和金额变动。

系统联动

系统比较个人实际已学内容、新班已讲内容和未来课表，而非仅比较班级第几讲。生效日起结束旧归班、建立新归班、取消旧未来安排并生成新安排；已学进度不重置，生效日前历史不改写。跨课程时保留原权益去向、新权益来源及补退差价依据。

异常与待决策

  • 新班比学生快时建立待补计划，比学生慢时处理重复内容，不自动把新班已讲内容算作学生已学。
  • 已预约补课、临时调班、考试或线上内容是否随转班迁移，要逐项纳入影响单。
  • 不同校区、版本、课时长度和价格之间的换算需明确；无法等价时不能伪装成无费用的普通转班。
  • 同一天有已完成和未完成课次时，以具体生效边界处理，避免按日期粗略删除全部安排。

15. 临时代课、长期换老师与停课

证据边界：参考平台可查看老师与教室课表（W3、W8），集团班级及调课列表包含教师信息（G3、G5）；本次没有验证专门的代课执行入口。

用户动作

  1. 从教师当天课表发起“安排代课”，选择受影响的一个或多个课次。
  2. 查看具备授课资格、时间可用的教师和必要交接材料。
  3. 确认代课范围、资料权限、需要通知的对象及必要薪酬规则。

系统联动

只修改所选课次的授课安排，保留班级主讲；向代课老师提供本讲教案、实际进度、必要学生信息和待处理事项。课后记录实际授课人。长期换老师使用独立任务，设置生效日期后更新主讲归属和未来指定课次。

异常与待决策

  • 代课与改变时间分开：需要调整时间时，额外检查学生、教师和教室冲突。
  • 代课老师临时取消，课次回到待安排，不自动选择不合格或冲突老师。
  • 已授课记录中的老师写错，走更正流程，不用“安排代课”覆盖历史事实。
  • 教师资格、跨校区可授课范围、临时代课薪酬与权限失效时间需机构配置。

16. 退课与退款：一张影响单，两条结果状态

已观察：参考平台区分课程费、教辅费和退费规则字段（W1、W3），退班入口未进入个体试算（W7）；集团有退费申请、教务确认、财务确认与查看等入口（G8）。以下金额模型和联动均为建议，需以已确认政策和购买时约定为准。

用户动作

  1. 从学生课程卡片选择“退课退款”，明确权益范围和原因；默认立即退出，未来生效使用单独的预约方式。
  2. 查看逐项试算：已收、已退、在途、实际已消耗、未消耗、优惠分摊、资料处理及例外调整。
  3. 同时查看未来将取消的课次、点名项、候补和临时安排；按既有权限完成确认或审批。
  4. 追踪“教学退出”和“资金退款”两项状态，异常交由明确角色处理。

系统联动

即时退出确认前重新读取进度和款项；如果预览后又上了一节课或已有其他退款，必须重新试算。业务提交成功后终止相应权益、使生效边界及以后的安排和预生成点名项失效、释放占位并预留退款金额。随后发起支付退款并依据渠道回执更新资金状态。

从教务视角，即时退出成功后，学生从该权益对应的未来有效点名册消失。底层建议标记“因退课取消”，保留关联原因，而非物理删除；历史授课、点名和课消继续可追溯。资金处理失败不自动恢复学生上课安排，恢复学习需要显式发起并重新检查权益和名额。

预约未来退出时，本次只登记预约和预计金额，生效前的正常上课安排继续有效。到达生效时间后，以实际课消和支付余额重新试算并按授权确认，再终止该边界及以后的安排和提交退款。不能把预约时的预计金额当成最终退款，也不能提前清掉生效前课次。

试算项目建议规则
金额依据按订单项和支付实收分配计算，不能仅用课程标价或整单应收。
优惠分摊下单时保存各课程及付费讲次的分摊快照；退款按购买时明确规则处理。
赠课保留来源与消耗顺序；赠课不按标准售价产生现金退款。
资料费作为可解释的独立项目，按既有领取及退费规则处理，不混入不明扣款。
组合优惠退一科后是否影响其他科优惠，依据购买时已明确政策；若重算，展示具体依据与差额。
退款上限累计成功退款加在途预留不能超过对应支付的可退实收；并发退款也必须遵守。

建议表达：试算退款 = 未消耗且可退权益对应的实收分配金额 + 有依据的可退附加项 − 已明示的调整项。实际可提交金额还受对应支付可退余额及其他在途退款预留限制。

示例，仅用于说明：10 讲课程，原价每讲 100 元，优惠 200 元，已全额实收 800 元；购买时等额分摊为每讲 80 元。按已确认规则消耗 4 讲，且无其他费用或退款，剩余 6 讲的示例退款为 480 元。不同讲次价格、部分支付、赠课与组合优惠需要按各自快照计算，不能套用这个平均数。

异常与待决策

  • 未来课次被误记为已上，应先更正与冲正，再计算退费，不能删除记录以降低消耗。
  • 退款处理失败、渠道超时、原路不可退和回执重复，需要可恢复的财务异常任务。
  • 允许退哪些权益、何时截止、材料处理、优惠是否重算、审批额度与线下退款凭证需明确。
  • 试算与审批期间是继续允许上课还是冻结安排，应由机构选择；无论哪种都要在最终提交时重新核验。

17. 营销活动与渠道归因

已观察：BOSS 按拉新、成交扩单、复购、转介绍、商城和素材组织能力（B1）；活动表单包含商品报名、在线收款、信息收集，支持来源、跟进人、校区、海报等配置（B3）。集团已有团报、二维码、短网址、资料分享和数据采集入口（G9）。

用户动作

  1. 选择目标：收集意向、预约体验、直接报名、老带新、套餐加购或拼团。
  2. 选择可售商品、适用校区、人群、时间和优惠规则，复用活动模板。
  3. 预览家长看到的页面、收集字段、报价及活动规则，再按权限发布。
  4. 在同一活动中查看从浏览、有效线索、跟进、支付到入班的结果。

系统联动

活动、二维码与分享链接携带明确渠道标识；信息收集进入去重和分配流程，商品报名进入统一报名与结算，支付成功后形成可兑现权益。渠道和推荐关系随订单保存，不要求员工事后在另一张表填归因。

BOSS 的推荐有礼页面说明可生成新学员、转介绍记录并发放券、账户金额或积分（B6）；这是产品说明，未实测。目标系统应明确奖励触发点是有效注册、付款还是完成退款观察期，并保留发奖、撤销和退费的关联。

BOSS 支付有礼表单可按线上商城、收银码、收款单及指定商品、满额或组合条件配置送券；支付后的推广内容可以是券、推荐有礼、分销、商品、微页面或群活码（B7）。页面说明付款完成后自动派券，但本次未保存或验证触发。可借鉴其“交易完成后继续引导下一步”的设计，目标平台仍需明确成功支付判定、重复回执去重和退款后的奖励处理。

异常与待决策

  • 同一家庭多个孩子不能仅凭手机号判定为同一学生；去重需要兼顾监护人与学生关系。
  • 已有客户参加新活动时，首触来源、此次活动来源和销售归属分别记录，避免相互覆盖。
  • 多渠道归因窗口、推荐人冲突、奖励可否叠加与退款后奖励回收规则需要明确。
  • BOSS 拼团表单可见模拟成团及虚拟浏览、转发、报名数开关（B5）；不建议沿用这些做法。经营指标应来自可追溯事件，演示数据应与正式报表隔离。

18. 自动匹配优惠、套餐与拼团

已观察：BOSS 有满减、折扣、礼品券；满减券可设置校区、课程、数量、门槛、固定或相对有效期、叠加、发放入口、人群和限领次数（B2）。集团学期优惠按有效期、年度、学期、年级和 1 至 5 科优惠配置，说明优惠期内所报课程汇总数决定优惠金额（G7）。自动最优组合在两平台均未完成实测。

用户动作

营销人员以一份规则配置适用范围、资格、时段、门槛、减免方式、叠加与互斥、预算和退款影响，并用典型订单试算后发布。前台报名时默认推荐满足规则的最低应付组合；需要保留券、偏好赠品等情况时，用户可查看其他合法组合与差异。

系统联动

报价引擎先判定资格和可组合性，再计算结果；展示命中的规则及不可用原因。订单保存规则版本与优惠分摊。确认时重新核验券余额、限次、活动名额与金额，防止使用已失效预览。人、Agent、线上商城和线下报名使用同一结算能力。内置老带新、双人同行和续费优惠模板，选择课程后发布独立优惠销售版本；学员卡片同步适用资格与待收费策略，成交后保存逐单快照。新优惠不能直接覆盖已付款历史金额，详见“课程商品化”章节。

活动类型执行时必须统一的逻辑异常处理
多科优惠明确统计口径、时间范围、学生维度、有效课程与历史报名是否计入。退科、转科、补报对优惠的影响按购买时规则处理。
优惠券资格、领取与使用限次、门槛、适用项、叠加和有效期。支付失败是否释放券、退款是否退券及退回后的有效期需明确。
套餐商品组成、可替换范围、套餐价向订单项和权益的分配。部分退课或部分售罄时，不得临时拼凑无法解释的退款金额。
拼团人数、时效、团长与团员资格、价格、奖励、成团后权益生效。未成团退款、已成团后成员退课、最后一席并发付款和课程停售需明确。

异常与待决策

“最优惠”需要明确优化目标：默认以当前合法组合中的实际应付最低为目标；现金抵扣、赠课、礼品和积分不能擅自折成同一现金价值。现有集团多科优惠和新券规则冲突时，应先建立优先级与互斥规则，再启用自动匹配。

19. 全 Agent 操控：把业务任务做成稳定能力

目标是让 Agent 从一句话完成上下文读取、方案生成、规则检查、授权范围内执行和结果确认。表单自动点击可以作为过渡方式，但关键业务应拥有稳定的任务接口；人与 Agent 使用同一身份权限、同一报价和同一变更规则。

用户动作

用户可以说“把这个学生周六这一讲调到周日同内容的班”“为老师明天的两节课安排代课”“计算这门课退出后应退多少钱”。Agent 只补问缺少且无法可靠推断的关键条件；已有上下文和授权持续有效，不要求重复选择学生、课程和同一权限。

系统联动

阶段需要具备的业务能力用户看到的内容
理解与定位解析目标、查找对象、同名消歧、识别时间和任务范围。“正在调整哪位学生的哪一讲”，必要时提供明确候选。
读取与规划查询进度、权益、名额、教师资格、报价和权限。推荐方案与可选方案，以及无方案的具体原因。
影响预览生成带数据版本的变更清单、金额依据和冲突检查。改什么、何时生效、费用怎样变化、是否需要其他角色处理。
按授权执行沿用机构权限、额度和已授予的操作范围；一次提交相互关联变更。允许自动执行的任务直接完成；超出授权才进入明确审批。
结果核验读回业务对象、支付或通知状态，关联任务编号。已完成的事实、仍处理中的部分和下一责任人。

首批开放能力

  • 查询学生课程、个人进度与可选课次；报名报价与确认报名；为已购权益选班。
  • 临时调班、永久转班和转课的预览及提交；安排代课；改期与停课。
  • 读取当日点名册、提交出勤、记录授课、按权限更正与冲正。
  • 退课退款试算与确认；查询审批、退款和通知结果；恢复失败任务。
  • 创建课程商品草稿、套用优惠模板、试算并发布优惠销售版本、生成学员订单收款码、查询真实效果。
  • 按授权创建与分配线索、本人保留、转交或释放公海、执行回收策略；从角色首页和顶部搜索续办任务。
  • 按校区、老师或学生及时间范围查询课表，筛选并对明确课次进行快捷操作。

异常与待决策

读数据、生成草稿和试算可直接运行；已明确授权范围内的常规操作可自动执行。收费、退款、价格例外、批量变更或对外发布是否需要进一步确认，取决于机构现有权限和本次授权，不设所有动作都要人工点一次的统一障碍。Agent 无权通过直接改表绕过规则，也不能把消息正文或上传资料中的文字当作系统授权。

每次任务保留发起人、实际执行身份、所用规则、影响预览和结果。访问范围按学生、校区、课程和职责限制；代课只开放必要课次资料。失败时返回能继续处理的业务原因，例如“目标课次已满”，而不是让用户重填整套表单。

20. 一次完成、重复不出错、失败可恢复

用户动作

在任务详情查看进展；网络中断后继续原任务；需要撤销时选择可用的恢复方案并查看影响。无须凭记忆检查多个列表是否都已更新。

系统联动

要求要避免的业务错误建议实现与验收观察
同一任务只生效一次重复报名、重复扣课、重复退费。任务有唯一标识；重试返回同一结果，不产生第二次业务变化。
确认前重新校验旧报价、旧进度、旧名额仍被提交。预览绑定数据版本；关键条件变化时返回差异并重新计算。
关联变更一起完成原班已取消，新班没有加入；权益终止，未来点名仍存在。核心业务提交完整成功或整体回退；对外动作保持可追踪状态。
消耗与退款协同同一份权益同时被上课扣除和现金退回。同一权益和支付余额在并发处理中保持一致约束。
金额分配守恒分摊尾差积累，累计退款超过实收。按最小货币单位计算，明确尾差归属，订单、支付、权益可对账。
更正保留原因历史课消或金额被直接覆盖，无法解释。记录更正或冲正关系，展示当前事实及可追溯的变化。
通知结果独立业务已成功但消息失败，被误判为整体失败后重复操作。通知可重试，业务不重复执行；展示发送中、成功或失败。

异常与待决策

资金、短信或第三方日历等外部系统不能假定与本地业务同一瞬间完成。需要分别定义待回执、失败重试、人工介入和最终关闭条件。撤销不是直接删记录；必须根据已发生授课、名额和支付情况判断可恢复范围。

21. 分期上线与迁移

以下顺序以业务依赖和风险为依据，不预设工期。每期先在可回放的脱敏样本和测试环境验收，再选定范围上线；实际范围需与现有技术实现核对。

阶段交付重点进入下一阶段的条件
第 0 期：事实与规则核对现有接口和自动同步；建立线索、员工身份、商品、优惠销售版本、学生、课程、章节、班级、课次、权益与订单的关系；确认归属保留/回收、扣课、退费和优惠政策。脱敏样本能解释每位学生的已购、已学、剩余和实收；缺失或冲突数据有处置清单。
第 1 期：最小招生与教学闭环身份与角色首页、顶部搜索；课程自动生成商城详情、三类基础优惠模板、优惠销售版本与扫码收款；扫码线索、销售保留/转交、公海管理员分配和基本回收规则；学生卡片、课程版本、多视角课表、报名选班、点名、临时调班、代课及退课。接入既有收退款能力并保留成交快照，Agent 与人工同时可用。此期按线索到履约的端到端切片逐步交付，不要求所有高级能力同时上线。核心链路可一次完成；权限、重复提交、名额和资金约束通过验收；不会制造孤立记录；教学退出有可追踪的资金处理结果。
第 2 期：营销与资金闭环扩展组合优惠与套餐、复杂推荐奖励、批量分配与回收模拟、渠道经营分析、资金异常对账、永久转班和跨课程权益迁移；基础归属、模板优惠与扫码收款已在第 1 期贯通。各报名渠道报价一致；优惠与退款可解释；奖励、订单和教学权益能追溯。
第 3 期：Agent 扩展与运营优化扩大可自动执行范围、批量处理、跨校区协调、规则模拟与经营分析。任务级权限成熟；失败可恢复；Agent 与人工对同一任务得到相同业务结果。

用户动作

教务、教师、招生和财务各提供典型业务样本及最常见异常，参与任务演练；按明确试点范围使用新工作台并反馈步骤与耗时。

系统联动

旧系统迁移期间，每类事实必须只有一个明确写入来源。新工作台可以先调用现有可靠能力，再逐步替换；不要让新旧两套同时独立维护学生课时或资金余额。保留映射、对账和可回滚边界，待稳定后关闭旧写入口。

异常与待决策

历史章节无映射、订单实收分配不全、重复学生和已退仍在班的记录需先治理。无法可靠还原的历史事实应标明来源与待核对状态，不凭规则猜补。高峰报名与结课期间的上线窗口、试点校区和回退责任人需共同确定。

22. 验收标准：测完整业务结果

以下是建议验收用例。效率指标先测当前基线，再设改造目标；不能凭设计图宣称已提效。除页面完成时间，还要测重复录入次数、跨页面跳转、纠错成本及跨模块结果一致性。

用例必须看到的结果
已付款但尚未开班的预购存在有效订单与权益、明确待选班状态；无需假班级；后续选班不重复收费。
课程改版后再次查看老订单老订单内容、优惠与规则快照不变；新班可选择新版本。
两班同讲号但内容不同不自动匹配；使用章节标识或已确认等价关系。
临时转班最后一个名额被并发占用只有一个成功占用；另一任务得到可继续处理的提示；原安排不会丢失。
临时转班成功后查看两班点名册原课次中失效，新课次中有效；后续归班保持约定；不存在重复履约安排。
学生永久转到进度更快的班保留个人已学进度，显示缺讲与待补安排，不自动补记已学。
老师只替代两节课仅两节课实际教师变化；主讲不变；代课资料访问限定范围。
请假和补课按已确认政策扣课或保留；补课关联原缺课；不重复消耗。
优惠券、多科优惠与套餐重叠计算合法组合，解释选中和排除原因；线上、线下与 Agent 报价一致。
预览退款后新增一节已消耗课程原预览失效并重新计算；未经更新不能按旧金额退款。
退课确认后支付退款失败未来有效点名册没有该学生，历史保留；资金显示异常并可重试，不自动恢复学习。
同一订单两门课同时退费成功退款加在途金额不超实收；分摊尾差可解释。
网络重试与重复支付回执报名、扣课、奖励和退款各只生效一次。
Agent 超出校区或操作额度受到与人工一致的权限限制；已完成的合规步骤和待授权步骤清晰分开。
新旧系统并行期每项业务有唯一写入来源；班级、个人剩余权益与资金记录可对账。
课程创建后进入商城草稿名称、适龄、大纲、课时和标准价已填充；内部教案不公开；公共文案调整能追溯来源。
同课程发布续费与双人同行版本共用课程履约内容，价格条件与二维码入口可区分；停用其一不改写另一个或历史订单。
客户扫码与员工代录重复线索关联同一客户及具体孩子；有有效归属时不被抢占；新触达仍记录活动来源。
销售采集与运营活动采集无归属冲突的新销售线索归本人保留；其他来源进公海，普通销售不能绕过管理员自行领取。
放弃保留与超时回收指定转交或进入公海有唯一结果，带上跟进记录；回收与跟进同时发生时复核最新状态。
上线新优惠后查看老学员收费新待收费项匹配资格与规则，已付款订单的原金额与规则快照不被追溯覆盖。
扫码码过期、停用或支付回执重复付款前解释状态并重新报价；有效支付只记一次；已支付但回执迟到进入核验，不能静默丢单。
校区、教师、学生三视角查同一课次筛选一致，临时转班与代课结果一致；点击办理后刷新原视图，无重复安排。
销售与校长登录或切换身份销售看到本人待跟进与数据，校长看到授权校区汇总；搜索、提示、明细与 Agent 均不越权。

用户动作

各角色按真实任务走完演练，核对最终名单、进度、权益、资金和通知，而不是只检查按钮是否可点击。

系统联动

为关键任务记录完成时间、补问次数、例外率、人工更正次数和结果读回；用真实业务事件生成统计，区分试点数据与正式数据。

异常与待决策

涉及资金、历史更正和并发名额的用例必须覆盖失败路径。生产小范围验收需要使用经过批准的业务样本，不以本次浏览器只读研究替代实际联调和资金核验。

23. 开发前需定稿的规则与补证清单

问题需要取得的证据或决策影响的模块
权益和扣课付费与赠课消耗顺序；请假、缺勤、补课、试听政策；部分购买内容边界。报名、点名、进度、退课。
内容等价课程版本、拆讲合讲、跨班与跨校区章节映射及维护责任。临时调班、永久转班、补课。
价格与退款购买时规则、优惠分摊、资料处理、分期实收分配、组合优惠回算和审批额度。报价、收款、退款、财务。
名额与排课占位期限、候补、临时虚位、冲突例外、停课和结课后更正规则。开班、选班、调班、代课。
营销与归因有效线索、重复客户、来源窗口、推荐奖励触发与回收、真实指标定义。活动、跟进、优惠、奖励。
