已明确的业务方向

领域目标设计
课程与教学课程设置包含讲次内容、适龄范围、资料与价格；班级关联课程、老师、学生与进度；课次独立保存实际授课、考勤与代课记录。
调整与退课临时调整指定学生、课程与目标班，默认章节一致；长期学生转班与多个班级迁移校区是两个功能。退课依据已上进度和实收款试算，确认后撤销未来点名，保留历史记录。
营销与商城课程事实复用为商品详情；优惠按模板、课程和条件配置，形成可追溯销售版本；支持老带新、双人同行、续费等；报名报价关联优惠，订单连接扫码收款。
CRM扫码或员工录入线索；来源、登记人和当前负责人分开。销售自录可保留，放弃后可转交；其他渠道进入公海；管理员分配，按规则提醒与回收。
课表老师和学生使用按日期、时间显示占用、空档与冲突的时间色块；教室、校区使用表格。支持对象与日期筛选，点击课次办理相关操作。
身份与操作按身份展示工作台和数据范围；搜索同时找对象与有权限的操作；一件事在同一界面填写必要信息，复用共享档案；搜索、界面与 CLI 共用操作目录。
界面紧凑统计栏、同排工具栏、蓝色下划线标签、统一 SVG 图标；表格不挤压中文，窄屏横向滚动；低频设置按需展开。

后续实施顺序

  1. 逐项验收端到端原型：线索→报名→支付确认→入班→考勤，以及调班、代课、退课、退款。
  2. 将剩余历史流程迁移到单一办理界面，统一必要字段、共享 ID 和数据更新契约；补齐实际场景中的搜索入口。
  3. 接入正式服务端：认证、动作权限、校区及记录范围、事务、版本检查、幂等、审计与跨账号同步。
  4. 接入真实支付、退款、通知、定时提醒与回收，再启用 Agent 和 siyue-cli 业务写入。
  5. 在不同身份、窗口宽度、缩放比例及真实数据规模下做完整验收。

当前 GitHub Pages 是公开前端演示，不代表上述正式能力均已上线。原方案中的计划项也不等于今天已交付。
