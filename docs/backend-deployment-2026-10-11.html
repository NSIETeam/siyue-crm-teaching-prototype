实际接入范围

范围已实现明确边界
员工账号与权限超管统一创建账号和随机初始密码；首次改密；修改既有账号角色、范围及单项授权；网页和 CLI 共用身份。校区按名称多选。认证仍为独立私有 JSON，单写进程；不是多租户系统。
CRM 与销售登记、导入、跟进、归属转交、公海与回收策略；服务器记录原登记人与归属历史。转化按首笔正额实收归属快照累计，小样本只展示人数。不足10条不显示百分比；当前无销售排名。自动回收只使用已发布策略。
报名与教务新生在报名页直接填必要资料；老生选择档案；批量新老生可混填。课程逐讲、建班、逐课次排期、转班、代课、考勤与课消共享关联。临时转班须满足对应年级、学科、课程/讲次、容量、时间和授权规则；不能任意跨课。
财务记录按订单、权益与课消核算；人工核实线下到账、退款申请/核准与线下退款凭据；金额用整数分。不发起外部付款或退款。商户支付渠道未配置，在线收款入口明确拒绝。
商城与优惠iPhone 样式预览、模块独立编辑、装修草稿与发布版本；课程商品发布快照与上下架；优惠券校验。拼团、联报仅可保存草稿，成团/多课程结算未接通，因此不能发布。未交付客户商城购买页面。
公开获客表单发布后提供独立客户填写链接；无需员工登录；按字段 ID 提交并生成回执；有效期、数量、限次和幂等校验；合格联系资料归集线索。只公开表单白名单，不公开员工资料与他人答案。手机号/访客限次不等于实名验证；不支持附件上传。
设置与日志校区、教室、字典、系统设置与职工业务档案接入；认证和业务日志统一检索，记录成功变更及拒绝/失败。数据库中的追加限制不等于外部防篡改审计；日志和备份需私有保管。

保留的界面方式

  • 首页数字合并为紧凑统计，常用办理最多6个入口，其余使用万能搜索。
  • 学生、员工、订单等记录点击后在本行下展开操作，再进入页面办理；顶栏统一返回。
  • 老师/学生课表使用填满格子的矩形时间色块，教室/校区使用横向表格；标示已记录课次和时间冲突。
  • 商城使用 iPhone 正面样式预览，各模块单独切换编辑并即时更新预览；草稿可恢复。
  • 表单用名称选择学生、课程、班级、老师、校区等对象，不要求员工手工填写内部编号。

API、CLI 与数据一致性

GET /v1/catalog 给出当前员工允许使用的运行操作及输入模型；GET /v1/state 返回已经过滤的数据与 revision。普通业务先预览、再确认，预览有效期10分钟，执行时重验会话、权限、输入、版本和幂等键。

同一事务写入业务变更、revision、幂等结果和成功审计。数据变更会使旧预览失效；不会静默覆盖其他人的办理。网页保存后重读服务器，其他获授权账号刷新可见。当前没有实时推送或离线合并。

siyue-cli plan … --input … --out … 生成私有预览计划；execute --plan … 执行同一计划。真实命令需员工登录；原 simulate lesson-consumption 仍为离线隔离模拟，不能导入正式数据库。

仓库中的早期37项操作契约及 backend/contracts/openapi.json 保留为设计资料。启用共享业务后，线上 /crm-api/openapi.json 从当前处理器动态生成实际运行契约；仅未启用业务的设计模式返回旧契约。当前实现使用 SQLite，早期 PostgreSQL、RLS、事务发件箱与支付回调方案未按该方案落地。

备份与恢复

备份工具导出独立 SQLite 快照与认证文件，校验数据库完整性并记录 SHA-256。备份目录0700、文件0600；不携带初始密码交付文件或 CLI 明文会话。定时器模板配置每天北京时间03:20执行，最多两分钟随机延迟。

测试已经把备份重新打开为业务库并核对记录和 revision。线上定时器是否已启用、首次执行是否成功，须以下面的发布记录为准；自动清理和异机副本尚未配置。

恢复需先停服、保留当前快照，在隔离目录核验备份及兼容代码，再切换私有文件。认证与业务快照不是跨两库原子时间点；恢复旧认证文件须清除旧会话并重新核对权限，避免旧登录或撤权状态复活。代码回滚不能覆盖已发生的业务数据。
