部署与数据边界

访问地址为 https://www.siyuejn.com/crm/。基础发布 46 个前端文件校验通过，HTTPS 证书和续期模拟通过，自动续期定时器及重载钩子已配置，原站点保持正常。

平台仍使用当前浏览器的 localStorage；阿里云、GitHub Pages 与本地文件的业务数据相互独立。后端设计骨架未启用，未接入真实登录、支付、数据库和跨账号同步。

临时转班：只选真正可用的目标

学生办理页与课次入口共用筛选逻辑。候选班级必须同年级、同学科、同课程、同讲次及版本；无完整课程资料、不存在的讲次或停用课程不参与匹配。提交时重新检查容量、时间冲突、校区规则、考勤状态和当前权限，不能通过改选参数绕过校验。

只调整本次课次的出勤名单；原班长期归属保留，临时班的课消仍归原订单。失败时同时恢复临调关系和待点名记录。专项检查：10 项通过。

批量报名：在错误行直接修正

校验页每行可更换学生、补齐电话和重新选班，提供可用的同课程班级建议；可移出本次或恢复，保留档案与已填草稿。改动后重新计算该学生的价格和优惠，重复报名、班级容量、待支付占位、时间冲突及同一学生电话冲突都会定位到行。

修改前不落业务；统一确认时才更新必要档案并创建待支付订单，付款前不生效。价格或容量在预览后发生变化，须重新核对；存储失败整批回滚。专项检查：12 项通过。

课消：共享订单、财务和退款口径

普通课消需对应学生、班级、有效实收订单和讲次快照，临时班沿用原订单归属。财务课消、学生进度与退款试算基于稳定 ID 关联，同名学生不会串单；金额按整数分分摊，累计不超出原实收，课消不改写付款记录。

CLI 载荷导入先预览，再由超级管理员确认；只合并 SIM 范围记录，按 ID 重映射索引，拦截重复导入和无效引用。导入失败回滚业务数组。课消及导入专项检查：18 项通过。

siyue-cli：实际执行十项模拟

新命令在隔离内存与存储中加载当前应用脚本，直接执行页面使用的点名保存处理器。课程、三名学员、两班、三张各 900 元订单及临转关系为明确标记的初始测试数据，没有真实收款或服务器调用。

实际结果为 3 条点名、2 次课消，共 600 元；原实收 2700 元，剩余可退 2100 元。生成模拟数据与报告两个 JSON 文件，可显式预览导入；不会自动修改当前浏览器。CLI 专项自动测试 3 项通过，包含实际子进程执行、结果检查、禁止覆盖旧文件及非法命令拒绝。
